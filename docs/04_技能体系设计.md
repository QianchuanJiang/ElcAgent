# 04 · 技能体系设计

> 技能体系是本项目的第三个核心模块。本文定义技能的声明式规范、完整技能清单、与相邻概念的边界，以及技能的治理机制。

---

## 1. 设计目标

技能是智能体与外部世界交互的**唯一通道**。设计技能体系要同时满足：

| 目标 | 判定标准 |
|---|---|
| 可声明 | 技能以配置形式注册，新增技能不改核心代码 |
| 可校验 | 输入输出受 schema 强约束，非法调用被拒并给出可读原因 |
| 可管控 | 权限、限流、超时、降级逐项可控且可观测 |
| 可治理 | 有版本、有健康度统计、有调用审计、支持热更新 |

**判断是否真的实现了技能管理**：把注册表换成硬编码的函数字典，系统还能否满足权限拦截、schema 校验、限流、降级这四项？不能，才说明技能管理是真的。

## 2. 技能定义规范

每个技能以声明式注册（配置文件形式），由技能调度器统一加载与调用。

| 字段 | 说明 |
|---|---|
| `skill_id` | 分组前缀 + 名称，如 `risk.calc_icing_load` |
| `name` / `description` | 名称 + **供模型读取的用途说明**（决定工具调用命中率，必须写清触发条件与不适用场景） |
| `category` | 所属分组 |
| `input_schema` / `output_schema` | JSON Schema，强校验 |
| `deterministic` | 是否确定性。影响是否允许缓存、是否可作为「证据」引用 |
| `owner_agents` | 允许调用的智能体白名单 |
| `permission_scope` | 最低岗位要求 |
| `rate_limit` / `timeout_ms` | 限流与超时 |
| `impl_mode` | 实现模式：`rule`（规则）/ `formula`（公式）/ `query`（查询）/ `model`（模型）/ `template`（模板） |
| `audit_level` | `none` / `summary` / `full`（是否记录完整输入输出） |
| `version` | 版本号，进入审计记录 |

### 2.1 `deterministic` 字段为什么重要

它决定了三件事：

1. **能否缓存**——确定性技能相同入参可安全缓存；非确定性（含模型调用）不行。
2. **能否作为证据**——结论溯源时，确定性技能的输出可作为可复算的证据；模型输出只能作为参考。
3. **路由策略**——确定性技能直接走代码，不进模型档位。

### 2.2 四级降级链

```
第 0 级 正常执行
   ↓ 失败
第 1 级 结果缓存命中（若可用）
   ↓ 无缓存
第 2 级 简化算法替代（精度下降但结果可用）
   ↓ 不可用
第 3 级 返回默认值（明确标注为占位数据）
   ↓ 不适用
第 4 级 返回 FAILURE（由调用方决定后续处置）
```

每次降级都记录 `fallback_level`，审计可还原真实执行路径。

### 3.7 `risk.*` 风险计算（6）

| 技能 | 用途 | 实现模式 | 确定性 |
|---|---|---|---|
| `risk.calc_icing_load` | 覆冰荷载估算（含增长趋势外推） | formula | 是 |
| `risk.calc_windage_margin` | 风偏间隙裕度校核 | formula | 是 |
| `risk.calc_lightning_trip` | 雷击跳闸概率估算 | formula | 是 |
| `risk.calc_thermal_rating` | 动态载流能力校核 | formula | 是 |
| `risk.rank_segments` | 综合打分与排序（三层加权） | formula | 是 |
| `risk.explain_factors` | 风险因子归因说明 | model + template | 否 |

**这是全项目最需要强调的一组**：`risk.calc_*` **全部为确定性物理公式，不使用模型**。

理由有三：① 公式可复算，模型输出不可复现，安全评审不接受后者；② 分层调度的原则是"实时阈值判断交给确定性计算"，而非交给模型；③ 把数值计算交给模型会引入无法追溯的误差。

模型只在两项介入：`meteo.parse_alert` 的语义解析，以及 `risk.explain_factors` 的归因说明。

## 4. 边界澄清

这四个概念经常被混用，需要明确区分：

| 概念 | 定义 | 本项目示例 |
|---|---|---|
| **技能 Skill** | 有明确输入输出契约、可被智能体调用的**能力单元**，通常是确定性计算或单次模型调用 | `risk.calc_icing_load` |
| **工具 Tool** | 技能的对外暴露形态（供模型做调用选择的 schema 视图） | 同一技能暴露给模型的工具定义 |
| **智能体 Agent** | 有目标、有状态、能编排多个技能并做决策的**执行主体** | 风险研判智能体 |
| **MCP** | 技能对外部宿主暴露的**协议**，本项目作为可选扩展 | 把 `history.*` 以 MCP 服务形式对外提供 |

一句话结论：**技能是能力，工具是技能的视图，智能体是主体，MCP 是出口。**

### 4.1 为什么技能不能直接等于函数

一个普通函数和一个技能的区别在于技能自带四件东西：

| 附带物 | 作用 |
|---|---|
| Schema | 输入输出强校验，非法参数在入口被拒 |
| 白名单与权限 | 只有授权的智能体和岗位可以调用 |
| 限流与超时 | 单技能独立配额，不拖垮主链路 |
| 降级链与审计 | 失败时有确定路径，调用有留痕 |

缺任何一项，它就只是个函数，不构成技能体系。

## 5. 技能治理

| 治理项 | 措施 |
|---|---|
| 注册与发现 | 启动时扫描注册表，校验 schema 合法性；发现冲突则拒绝启动（快速失败） |
| 版本管理 | 技能与智能体均带版本号，进入审计；支持多版本灰度路由 |
| 权限 | `owner_agents` 白名单 + `permission_scope` 岗位要求，双重校验 |
| 限流 | 每技能独立配额，超限返回失败并提示，**不阻塞主链路** |
| 缓存 | 确定性技能 + 相同入参 → 结果缓存（TTL 可配） |
| 审计 | `audit_level = full` 的技能记录完整输入输出，其余记录摘要 |
| 热更新 | 规则包与映射表支持运行时重载，前端可见生效版本变化 |
| 健康度 | 统计调用次数、成功率、P95 耗时、缓存命中率、降级次数 |

### 5.1 健康度指标为什么重要

五个指标各自回答一个诊断问题：

| 指标 | 回答的问题 | 异常时意味着 |
|---|---|---|
| 调用次数 | 这个技能是否被真的用上 | 长期为零 → 设计冗余或路由错误 |
| 成功率 | 实现是否稳定 | 偏低 → 逻辑缺陷或依赖不稳定 |
| P95 耗时 | 是否成为链路瓶颈 | 偏高 → 需要缓存或算法优化 |
| 缓存命中率 | 缓存策略是否有效 | 偏低 → 入参离散度过高 |
| 降级次数 | 失败是否被静默掩盖 | 偏高 → 底层依赖有系统性问题 |

没有这五个指标，技能体系是"黑箱可用"；有了它们，才是"可运维"。

### 5.2 前端呈现

技能注册表页面应展示每个技能的健康度，并提供**启用开关**——关闭某个技能后重跑任务，可以直观看到降级路径被触发。这是验证技能治理是否真实生效的最直接方式。

## 6. 实现要点与常见陷阱

| # | 陷阱 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 注册表硬编码为函数字典 | 无权限、无限流、无降级，不构成技能体系 | 配置化注册 + 启动时扫描校验 |
| 2 | 技能描述写得模糊 | 模型选错技能或该调不调 | `description` 写清触发条件与不适用场景 |
| 3 | 数值计算交给模型 | 结果不可复算，审计不通过 | 公式类技能标记 `deterministic`，不走模型 |
| 4 | 不过滤入参 | 非法参数引发下游异常 | schema 强校验，入口拦截 |
| 5 | 限流失败阻塞主链路 | 一个技能拖垮全局 | 限流只影响该技能及其降级路径 |
| 6 | 降级静默发生 | 审计无法还原真实路径 | 记录 `fallback_level` |
| 7 | 缓存非确定性技能 | 结果被错误复用 | 仅 `deterministic = true` 的技能可缓存 |
| 8 | 无健康度指标 | 系统黑箱，无法运维 | 五个核心指标 + 前端展示 |
| 9 | 智能体可绕过技能直连数据 | 审计断链、权限失效 | 取数入口唯一，越权调用抛异常 |
| 10 | 技能无版本 | 行为变更无法追溯 | 版本号进入审计记录 |
