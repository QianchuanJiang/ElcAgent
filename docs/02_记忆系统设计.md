# 02 · 记忆系统设计

> 记忆系统是本项目的第一个核心模块。本文定义记忆的分类体系、生命周期、数据模型、检索策略、冲突消解机制与可解释性设计。

---

## 1. 设计目标

多数智能体项目的所谓"记忆"，实际是把历史对话或检索结果拼进提示词。这种做法有三个问题：无法回答「记住了什么」、无法回答「为什么用这条」，也无法处理新旧知识矛盾。

本项目的记忆系统定位为**结构化的记忆生命周期管理**，需要满足四个可验证的目标：

| 目标 | 判定方式 |
|---|---|
| 可写入 | 记忆的产生有明确触发条件与流水线，非隐式拼接 |
| 可检索 | 检索过程可分解、可调参、可观察每一路的贡献 |
| 可解释 | 每条结论能回答「引用了哪几条记忆、各得多少分、是否真被采用」 |
| 可演进 | 支持新增、更新、冲突消解、衰减归档与版本链追溯 |

---

## 2. 记忆分类体系

分三层共十类。**三层的划分依据不是存储位置，而是作用域、权限边界与衰减参数的不同。**

| 层 | 类 | 内容 | 存活周期 | 半衰期 |
|---|---|---|---|---|
| **短期** | 会话缓冲 | 原始多轮对话消息 | 会话 + 7 天 | 不衰减 |
| | 任务工作记忆 | 当前任务的中间产物（含共享状态快照） | 任务 + 1 天 | 不衰减 |
| | 滚动摘要 | 超出窗口后的对话压缩摘要 | 会话 + 7 天 | 不衰减 |
| **长期** | 语义记忆 | 口径标准、术语、阈值、设备参数、规则原文 | 长期 | **不衰减** |
| | 情节记忆 | 历史灾害事件、研判案例、处置结果 | 长期 | 180 天 |
| | 程序记忆 | 标准作业流程、成功的技能调用序列、方案模板 | 长期 | 365 天 |
| | 反思记忆 | 误判复盘、人工修正结论、失败教训 | 长期 | 90 天 |
| **用户** | 画像 | 姓名、岗位、辖区、职责、权限等级 | 长期 | 不衰减 |
| | 偏好 | 输出风格、模板偏好、单位口径、常用灾害类型 | 长期 | 365 天 |
| | 行为 | 历史决策、常看线路、审批习惯、纠错记录 | 长期 | 120 天 |

### 2.1 为什么用户记忆必须独立成层

长期记忆是**组织知识**，用户记忆是**个人知识**。二者在三个方面完全不同：

| 维度 | 长期记忆 | 用户记忆 |
|---|---|---|
| 作用域 | 全局可见 | 按 `user_id` 隔离 |
| 检索策略 | 按语义相关性召回 | **强制注入**当前用户上下文 |
| 权限边界 | 受数据分级约束 | 同时受岗位权限约束 |
| 衰减参数 | 按知识类型区分 | 更短（偏好与行为会变） |

把两者混在同一个向量库里，会导致切换用户时系统行为毫无变化——用户记忆形同虚设。这是许多 Demo 的通病，也是本项目刻意规避的设计点。

## 3. 记忆生命周期

### 3.1 写入流水线（7 步）

| 步骤 | 动作 | 关键参数 |
|---|---|---|
| 1 候选抽取 | 从会话或任务结果中抽取结构化记忆候选 | 轻档模型 + 结构化输出约束 |
| 2 归一化 | 统一术语、单位、时间格式、编码（复用治理层映射表） | 与治理层共用映射 |
| 3 去重 | 与已有记忆做向量相似度比对，`sim > 0.92` 视为重复 → 更新而非新增 | 阈值可配 |
| 4 冲突检测 | 与已有记忆语义矛盾时建立 `contradicts` 关系边 | 模型判定 + 规则兜底 |
| 5 冲突消解 | 按权威优先级裁决，无法裁决则标记待人工 | 见第 5 节 |
| 6 重要度打分 | `importance = 0.4×显式重要性 + 0.3×访问频次归一 + 0.3×结果反馈` | 结果反馈来自审批采纳与否 |
| 7 落库与索引 | 关系库写入 + 向量索引写入 + 事件广播 + 审计记录 | **必带 `source_ref` 与 `confidence`** |

**第 7 步是硬约束**：没有来源引用的记忆不允许落库。这条约束保证任何一条记忆都能追溯回产生它的那次任务或那次审批。

### 3.2 检索流水线（6 步）

| 步骤 | 动作 | 关键参数 |
|---|---|---|
| 1 查询改写 | 把自然语言改写为检索式，并抽取元数据过滤条件 | 轻档模型 |
| 2 多路召回 | 向量路 Top-30 ∪ 词法路 Top-30 ∪ 元数据精确过滤结果 | 三路并行 |
| 3 融合 | 倒数排名融合：`score_rrf = Σ 1/(60 + rank_i)` | k = 60 |
| 4 重排 | 交叉编码器对 Top-20 重排 | 无重排模型时跳过并标注 |
| 5 加权 | 综合得分计算（见 3.4） | 参数可配 |
| 6 过滤与组装 | 作用域过滤 + 权限门禁 + Top-6 注入，单条截断 300 字 | 带来源标注 |

> **为什么用三路而不是只用向量**：向量路擅长语义相似，但对线路编码、设备型号、条款号这类精确标识符召回能力弱；词法路正好补这一点。元数据过滤则解决「只要某地市的数据」这类硬约束。三者互补，缺一都会出现典型漏召回。

### 3.3 衰减与归档

```
decay(memory, now) = exp( -ln2 × Δt_days / half_life_days )

final_score = base_score
            × (0.7 + 0.3 × importance_norm)
            × decay(memory, now)
            × scope_boost
```

| 参数 | 取值 |
|---|---|
| `scope_boost` | 用户记忆 1.2，情节记忆 1.0，语义记忆 1.0 |
| 各类型半衰期 | 见第 2 节表格 |
| 归档条件 | `decay < 0.15` 且 `access_count = 0` 且距今 > 90 天 |
| 归档行为 | 转为 `archived` 状态，**保留可查，不删除** |

**单独说明**：衰减只影响检索排序，不触发删除。语义记忆（口径、阈值、术语）永不衰减——规范不会因为时间久远而失效。这是审计要求决定的。

### 3.4 巩固机制

| 触发 | 动作 |
|---|---|
| 会话结束 | 短期记忆蒸馏为 1 条情节记忆 + 若干条候选语义记忆 |
| 任务完成 | 成功的执行路径转为程序记忆候选（待审批确认后转正） |
| 每日定时 | 重算所有记忆的衰减分与重要度；合并反复出现的候选；将高访问低重要度的记忆提升 |

**巩固是记忆系统从「记录」变成「学习」的关键**。没有巩固，记忆只是一个不断增长的日志。

## 4. 记忆数据模型

### 4.1 记忆主表 `memory_item`

| 字段组 | 字段 | 说明 |
|---|---|---|
| 主键 | `memory_id` | 全局唯一 |
| 作用域 | `scope_type` / `scope_id` | `session` / `global` / `user` / `org` + 对应 ID |
| 分类 | `mem_type` | 七种记忆类型枚举 |
| 内容 | `title` / `content` / `structured_payload` | 标题（≤30 字）+ 自然语言正文（≤500 字）+ 结构化字段 |
| 溯源 | `source_type` / `source_ref` | 来源类型 + `trace_id` 或 `message_id`（**必填**） |
| 可信 | `confidence` | 0~1，来自抽取时的模型置信度或人工确认 |
| 权重 | `importance` / `access_count` / `last_access_at` / `decay_score` | 用于检索加权 |
| 效力 | `valid_from` / `valid_until` / `status` | 时效窗口；`active` / `archived` / `disputed` / `superseded` / `rejected` |
| 安全 | `sensitivity_level` / `owner_user_id` | 数据分级 + 归属人 |
| 索引 | `tags` / `embedding_ref` | 标签数组 + 向量索引引用 |

### 4.2 配套表

| 表 | 作用 |
|---|---|
| `memory_edge` | 记忆间关系图：`derived_from` / `contradicts` / `supersedes` / `related` / `supports`，含权重与建立理由 |
| `memory_access_log` | 每次检索命中记录：查询、命中记忆、三路得分、融合得分、调用方、耗时、**是否被最终结论采用** |
| `session` / `session_summary` | 会话与滚动摘要 |
| `user_profile` / `user_preference` / `user_behavior_event` | 用户记忆三张表 |
| `memory_consolidation_log` | 巩固与衰减的每次执行记录 |

### 4.3 关于 `supersedes` 版本链

当口径标准发生变更（例如某阈值从旧值调整为新高值），系统**不删除旧记忆**，而是建立 `supersedes` 关系，并保留双方的可查性。

原因：复盘场景必须能够回答「当时那次研判依据的是哪一版口径」。如果直接覆盖，历史结论将失去解释依据。这是审计合规的硬要求，不是设计偏好。

### 4.4 `used_in_output` 的意义

`memory_access_log` 中有一列 `used_in_output`，区分「被检索到」与「真的被用上」。

这一列的价值在于它能回答一个尖锐的问题：**这些记忆到底有没有用？**

- 检索命中率高但使用率低 → 检索策略需要调整（召回不准）
- 使用率高但查询重复度高 → 缺少相似记忆合并
- 长期零访问 → 应归档

没有这一列，记忆系统只能证明"我检索了"，无法证明"检索有用"。

## 5. 冲突消解策略

当新旧记忆矛盾时，按以下权威优先级裁决，先命中者胜：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 人工确认（审批意见） | 最高权威，直接建立 `supersedes` 边 |
| 2 | 规则库 / 标准文件导入 | 正式发布的阈值与口径 |
| 3 | 模型抽取 + 高置信度（≥ 0.8） | 需同时建立 `contradicts` 边 |
| 4 | 模型抽取 + 低置信度 | 不覆盖旧记忆，标记 `disputed` |
| 5 | 会话推测 | 仅入短期记忆，不写长期 |

**无法裁决时的处理**：两条记忆同时保留，状态标记为 `disputed`，在记忆中心出现待仲裁提示，提供一键仲裁入口。仲裁后建立 `supersedes` 关系，旧版转为 `superseded` 状态但保留可查。

### 5.1 冲突记忆 ≠ 数据质量问题

这是两个层面、完全不同性质的问题，容易被混淆：

| | 数据质量问题 | 记忆冲突 |
|---|---|---|
| 层面 | 数据层 | 知识层 |
| 表现 | 编码不一致、字段缺失、单位不符、数值异常 | 同一事实存在两个版本的表述 |
| 成因 | 数据写入不规范 | **规范本身发生过变更** |
| 处理者 | 数据治理智能体 | 记忆冲突消解 + 人工仲裁 |
| 处置 | 映射、校验、归一、隔离 | 建立版本链，不用删除 |

第二种在长期运行的系统中是常态而非异常。把两者混为一谈，会导致要么误删有价值的旧知识，要么放任脏数据污染知识库。

## 6. 与智能体的接口约定

记忆管家对外只暴露 8 个技能，**其他智能体不允许直接访问记忆库**：

| 技能 | 输入 | 输出 | 调用者 |
|---|---|---|---|
| `memory.search` | 查询、作用域过滤、类型过滤、Top-K | 记忆列表（含得分与来源） | 全部执行层智能体 |
| `memory.write` | 内容、类型、作用域、来源引用、置信度 | `memory_id` | 仅记忆管家内部 + 审批回填 |
| `memory.update` | `memory_id`、补丁、变更理由 | 更新后记忆 | 记忆管家内部 |
| `memory.conflict_resolve` | 候选记忆、已存在记忆 | 裁决结果 | 记忆管家内部 |
| `memory.decay_run` | 基准日期 | 影响统计 | 定时任务 |
| `memory.consolidate` | 会话 ID 或任务 ID | 新生成记忆列表 | 事件触发 |
| `memory.profile_get` | `user_id` | 画像 + 偏好 + 行为摘要 | 会话网关 / 用户画像 |
| `memory.profile_upsert` | `user_id`、补丁、来源引用 | 更新后画像 | 用户画像 / 审批协同 |

**统一约束**：所有读操作返回体必须包含 `retrieval_mode`（`hybrid` / `degraded`）、`hit_count`、`latency_ms`，供前端展示与审计使用。

## 7. 可解释性设计

这是把记忆系统"讲清楚"的关键，共五个可视点：

| # | 可视点 | 内容 |
|---|---|---|
| 1 | 记忆卡片 | 类型徽章、作用域、重要度条、衰减条、置信度、来源可点击跳转 |
| 2 | 命中高亮 | 结论中引用记忆的字段旁出现记忆标记，悬停显示命中记忆原文与该记忆对结论的贡献 |
| 3 | 记忆时间线 | 按时间轴展示一次任务中各记忆的检索与写入时刻，形成可视的「记忆流」 |
| 4 | 访问热力 | 展示每条记忆的访问次数与最近访问时间，回答「哪些记忆真正在被用」 |
| 5 | 冲突看板 | 待仲裁记忆列表 + 关系图 + 一键仲裁入口 |

### 7.1 检索实验室（推荐实现）

一个专门用于「证明检索不是黑盒」的交互工具：

| 区域 | 内容 |
|---|---|
| 输入区 | 查询文本 + 作用域/类型筛选 + **权重滑块组**（向量权重 / 词法权重 / 重要度权重 / 时效权重） |
| 三路并排 | 向量路 Top-10（含相似度）｜词法路 Top-10（含词法分）｜融合重排后 Top-6（含各分项贡献拆解） |
| 打分拆解 | 选中任一条，显示综合得分公式的逐项代入计算 |
| 参数实验 | 拖动权重滑块，三路结果与最终排序实时变化 |

**价值**：把「我们用了混合检索 + 重排 + 时效衰减」这句话，变成可被拖动验证的事实。拖动时效权重让一条陈旧的规范降权，比任何文字说明都有说服力。

## 8. 记忆效果的验证方案

记忆系统的效果必须通过对照实验证明，而非声明。

### 8.1 有记忆 vs 无记忆（同一任务执行两遍）

通过一个全局记忆开关实现：关闭时检索跳过全局与用户作用域（仅保留本次会话短期记忆），并跳过巩固流程。

| 指标 | 期望差异 |
|---|---|
| 端到端耗时 | 明显下降（命中记忆减少重复的解析与检索） |
| 模型调用次数 | 下降（程序记忆直接复用处理路径，跳过部分规划） |
| 输入 token 量 | 显著下降（口径映射关系已沉淀，不再全量推算） |
| 风险排序稳定性 | 更稳定（历史案例约束了打分离散度） |
| **最终结论** | **应保持一致** |

> **最后一行是刻意保留的**：主动说明「记忆主要提升效率与一致性，不改变物理计算的结果」，比宣称记忆无所不能更能建立专业信任。

### 8.2 用户 A vs 用户 B

切换不同岗位角色，验证用户记忆的差异化效果：

| 维度 | 运检值班员 | 安全监督专责 |
|---|---|---|
| 默认辖区 | 本地市 | 全省 |
| 输出风格 | 操作导向、要点式、含派工建议 | 合规导向、含风险等级与条款依据 |
| 简报模板 | 值班版 | 监督版 |
| 记忆注入 | 常用线路、历史派工记录 | 历史事故复盘、合规检查项 |
| 权限过滤 | 本辖区全量 + 其他地市摘要 | 全省全量 + 审计视图 |

### 8.3 记忆验证清单

| # | 验证项 | 通过标准 |
|---|---|---|
| 1 | 关闭记忆重跑同一任务 | 指标明显变差 |
| 2 | 手改一条记忆内容后重跑 | 结论跟着变化 |
| 3 | 注入两条冲突记忆并仲裁 | 系统行为改变，旧版仍可查 |
| 4 | 查某条记忆的访问日志 | 能看到谁在何时因何查询命中它 |
| 5 | 把某条记忆的最近访问时间往前调 180 天 | 其检索排序下降 |

## 9. 实现要点与常见陷阱

| # | 陷阱 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 把记忆等同于「对话历史拼接」 | 无法检索、无法解释、无法演进 | 结构化为独立的记忆条目与生命周期 |
| 2 | 用户记忆与长期记忆混存 | 切换用户无差异，用户记忆形同虚设 | 独立作用域 + 独立衰减 + 强制注入 |
| 3 | 只用向量检索 | 编码、型号、条款号等精确标识符漏召回 | 向量 + 词法 + 元数据三路融合 |
| 4 | 检索结果直接全部注入 | token 成本高、噪声大 | 融合重排后 Top-K + 时效加权 |
| 5 | 允许无来源记忆落库 | 无法追溯，审计不通过 | 强制 `source_ref` + `confidence` |
| 6 | 冲突时直接覆盖旧记忆 | 历史结论失去解释依据 | 保留版本链，`superseded` 状态可查 |
| 7 | 只记录「检索到了」不记录「用上了」 | 无法评估记忆价值 | 记录 `used_in_output` |
| 8 | 无巩固机制 | 记忆只增不减，逐渐退化 | 会话/任务/定时三级巩固 |
| 9 | 衰减触发删除 | 审计断链 | 衰减只影响排序，低分转归档不删除 |
| 10 | 语义记忆参与衰减 | 阈值、口径等长期有效知识被错误降权 | 语义记忆半衰期设为无穷 |
