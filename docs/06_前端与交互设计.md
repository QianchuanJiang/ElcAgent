# 06 · 前端与交互设计

> 本文定义前端的信息架构、页面设计、关键交互、可视化方案与工程约束。

---

## 1. 设计定位

**结论：前端的核心叙事是「看智能体工作」，而非「和智能体聊天」。**

聊天界面在演示上最直观，但无法传递架构复杂度——任何检索增强生成的应用都能做一个聊天框。而「能看见消息在智能体之间流动」「能看见记忆被哪一步引用」才是架构能力的直接证据。

因此八个页面中，权重最高的是三个**机制可视化页面**：

| 优先级 | 页面 | 承担的作用 |
|---|---|---|
| 最高 | 记忆中心 | 展示三层记忆的产生、检索、命中、冲突、衰减 |
| 最高 | 协同可视化 | 展示消息协议、因果链、仲裁与熔断 |
| 最高 | 审计溯源 | 展示全链路可追溯能力 |
| 高 | 研判工作台 | 承载主业务流程，串联上述三者 |
| 中 | 简报中心 · 技能与规则 | 展示产出物与可插拔性 |
| 中 | 态势大屏 · 对话入口 | 建立规模感与降低初次接触门槛 |

## 2. 视觉语言

### 2.1 三色语义体系（全局一致）

三个核心模块各分配一个专属色，贯穿全局形成可被记住的视觉语言：

| 模块 | 色值 | 应用位置 |
|---|---|---|
| **记忆** | `#A855F7` 紫 | 记忆徽章、命中高亮、记忆时间线、记忆抽屉 |
| **协同** | `#06B6D4` 青 | 消息流、时序图、拓扑边、技能标签 |
| **审计** | `#64748B` 灰蓝 | Trace 树、版本号、来源引用角标 |

> **设计价值**：当一条结论旁同时出现紫色与青色标记时，不需要解释就能知道「这条结论综合了记忆与智能体协同的结果」。颜色本身就是架构说明。

### 2.2 主色板（深色作战室主题）

```yaml
background:      "#0B1220"   # 深海军蓝底
surface:         "#131C2E"   # 卡片面
surface_raised:  "#1B2740"   # 悬浮 / 选中
border:          "#24324A"   # 边框与分隔
text_primary:    "#E8EDF5"
text_secondary:  "#93A2BC"
text_muted:      "#5C6B85"

accent_primary:  "#3B82F6"   # 主操作
risk_high:       "#EF4444"   # 高风险
risk_medium:     "#F59E0B"   # 中风险
risk_low:        "#10B981"   # 低风险 / 正常

memory:          "#A855F7"
collab:          "#06B6D4"
audit:           "#64748B"
```

**风险配色说明**：高风险用红、低风险用绿，符合国内电力行业的告警惯例（红 = 危险），与欧美金融市场的涨跌配色语义相反，此处以国内行业惯例为准。

浅色主题作为可选项（投影或打印场景），保持相同的语义映射。

### 2.3 排版规范

| 项 | 规范 |
|---|---|
| 中文正文 | 系统无衬线字体，14px，行高 1.6 |
| 数字与指标 | 等宽字体并启用 tabular-nums，保证指标跳动时不抖动 |
| 标题层级 | 20px / 16px / 14px，克制使用 |
| 栅格 | 12 列，间距 16px，基线 8px |
| 密度 | 默认紧凑（表格行高 36px）——信息密度高本身就是专业性的一部分 |

### 2.4 状态色语义

| 状态 | 表现 |
|---|---|
| 运行中 | 青色呼吸光晕 |
| 完成 | 绿色对勾，无动效 |
| 降级 | 橙色感叹号 + 悬停显示降级层级 |
| 熔断 / 待人工 | 红色暂停图标 + 醒目背景 |
| 缓存命中 | 灰色闪电图标 + 标签 |

```
│ 侧栏     │                                                          │
│ (200px)  │                    主内容区                              │
│          │                                                          │
│ 态势大屏 │                                                          │
│ 研判工作 │                                                          │
│ 协同可视 │                                                          │
│ 记忆中心 │                                                          │
│ 审计溯源 │                                                          │
│ 简报中心 │                                                          │
│ 技能规则 │                                                          │
│ 对话入口 │                                                          │
│ ─────    │                                                          │
│ 运行状态 │                                                          │
│ 消息总数 │                                                          │
│ 记忆条数 │                                                          │
│ 今日任务 │                                                          │
└──────────┴─────────────────────────────────────────────────────────┘
```

### 3.2 四个全局控件

| 控件 | 作用 | 为什么必须是全局的 |
|---|---|---|
| **记忆开关** | 启用 / 禁用长期记忆与用户记忆 | 记忆效果对照实验的前提 |
| **用户切换** | 切换岗位角色，联动视图与输出风格 | 用户记忆差异化验证的前提 |
| **模型档位** | 显示与切换当前模型档位 | 分层调度与环境无关性的可视化 |
| **演示场景** | 一键跳转到预置场景 | 保证演示节奏，避免现场手动输入出错 |

**侧栏底部常驻三个数字**（消息总数、记忆条数、今日任务数）——让「系统在运行」这件事始终可见。

## 4. 页面设计

### 4.1 态势大屏

**目标**：30 秒内建立「这是覆盖全省线路的严肃系统」的认知。

| 区域 | 内容 |
|---|---|
| 顶部指标条 | 在运线路 / 覆盖杆塔 / 活跃预警 / 待办数 / 当前模型档位 / 系统状态 |
| 主体地图 | 行政区划底图 + 线路折线（电压等级决定线宽）+ 气象站点 + 预警影响范围 + **区段风险着色** |
| 右侧面板 | 预警列表 / 风险区段榜（带评分条与因子简标）/ 最近任务流 |
| 底部曲线 | 四要素时序联图（气温 / 湿度 / 风速 / 覆冰），灾害窗口用竖向高亮带标注 |

**交互**：点击区段弹出区段卡片（基础属性 / 当前风险分 / 风险因子 / 关联历史案例 / 监拍缩略图 / 「对此区段发起研判」）；曲线悬停联动地图高亮。

**技术要点**：地图只渲染离线行政区划数据，**不接在线底图，规避边界合规风险**；区段着色用画布图层而非 DOM，保证上千个区段的渲染性能。

### 4.2 研判工作台（主战场）

**目标**：让观众看见一条预警如何被多个智能体接力处理成一份可签发的简报。

| 区域 | 内容 |
|---|---|
| 顶部对比条 | 三张指标卡：端到端耗时 / 模型调用次数 / 输入 token。显示当前值、上次值与变化百分比 |
| 左栏 输入区 | 灾害类型 / 时间窗 / 线路范围 / 自然语言输入 / 高级选项（置信度阈值、记忆范围、模型档位）/ 开始研判 |
| 中栏 执行流 | 按执行阶段分组的时间轴。每个智能体一张卡片：名称与状态徽章、关键输出摘要、耗时与 token。卡片间以连线表示依赖。**记忆命中时卡片亮起紫色标记，可展开命中的具体记忆** |
| 右栏 结果区 | 风险清单 / 相似案例 / 规则越限 / 方案建议 / 简报预览 五个标签页 |
| 底部状态栏 | trace 标识（可跳审计页）/ 消息数 / 记忆命中数 / 降级次数 / 缓存命中率 / 导出 |

**执行流的节奏设计**：三阶段时间分配要有意识地控制——理解与准备阶段应快速通过（建立"反应快"的印象），研判与校验阶段为主要表演时段，产出阶段用流式输出展示简报逐段生成，最后停在「待审批」状态。

**关键交互**：
1. 任意结果字段悬停 → 显示溯源标记，点击打开溯源抽屉；
2. 风险评分点击展开三层打分构成（物理 / 规则 / 语义）的瀑布图；
3. 规则越限项点击跳转规则包并定位；
4. 置信度徽章点击展开四路来源构成；熔断时显示原因清单。

### 4.3 协同可视化（核心证据页）

**目标**：把「多智能体通信机制」从一个概念变成可以指着说的画面。

| 视图 | 内容 | 技术 |
|---|---|---|
| **消息时序图**（主视图） | 横轴时间，纵轴智能体（按层级排列）。每条消息一根箭头线，线色按言语行为区分，里程碑用垂直虚线标注 | 刻度计算 + SVG 增量渲染 |
| **智能体拓扑图** | 有向图，节点按层级分层布局，节点大小反映处理消息数，边粗细反映通信频次。当前执行节点呼吸高亮，消息沿边流动 | React Flow |
| **实时消息流** | 滚动列表：时间戳 / 发送方→接收方 / 言语行为徽章 / 意图 / 耗时 / 状态。点击展开信封详情 | 虚拟滚动 |

**三视图联动（这一页的灵魂）**：

| 操作 | 联动结果 |
|---|---|
| 点击时序图某条消息 | 拓扑图高亮该边 → 消息流滚动定位 → 右抽屉打开信封详情 |
| 点击拓扑图节点 | 时序图过滤为该智能体相关消息 → 消息流同步过滤 |
| 开启「只看关键路径」 | 隐藏通知类与广播类消息，画面变清爽 |

**信封详情抽屉**分四块，与信封结构一一对应：基础信息 / 载荷摘要 / 上下文引用（记忆可点击跳记忆中心，技能可点击跳技能页）/ 遥测（模型、token、耗时分解条形图）。

**为什么这一页能证明架构能力**：任何套壳应用都无法产出「带父子关系的因果树 + 按言语行为分类的消息 + 耗时分解 + 上下文引用清单」。

### 4.4 记忆中心（最重要页面）

**目标**：把「三层记忆」从名词变成可浏览、可检索、可验证、可干预的对象。

**顶部指标条**：记忆总量 / 类型分布 / 今日新增 / 平均检索命中率 / 待仲裁冲突数。

五个标签页：

#### 标签页 1 · 记忆库

| 项 | 设计 |
|---|---|
| 视图切换 | 表格视图（展示规模）/ 卡片视图（逐条讲解） |
| 筛选器 | 类型 / 作用域 / 状态 / 标签 / 置信度区间 / 重要度区间 / 时间范围 |
| 每条展示 | 标题 / 类型徽章 / 作用域 / **重要度条** / **衰减条** / 置信度 / 访问次数 / 状态徽章 |
| 行操作 | 详情 / 查看来源 / 归档 / 标记待仲裁 / 查看关系图 |

**记忆详情抽屉**四段：正文 / 结构化字段 / **关系图**（与其他记忆的派生、矛盾、替代关系）/ **访问历史**（谁在何时因何查询命中，含是否被最终采用）。

#### 标签页 2 · 检索实验室（最亮眼的功能）

| 区域 | 内容 |
|---|---|
| 输入区 | 查询文本 + 作用域与类型筛选 + **权重滑块组**（向量 / 词法 / 重要度 / 时效） |
| 三路并排 | 向量路 Top-N（含相似度）｜词法路 Top-N（含词法分）｜融合重排后 Top-K（含各分项贡献） |
| 打分拆解 | 选中任一条，显示综合得分公式的逐项代入计算 |
| 参数实验 | 拖动权重滑块，各路结果与最终排序实时变化 |

**价值**：把「用了混合检索 + 重排 + 时效衰减」这句话，变成可被拖动验证的事实。

#### 标签页 3 · 记忆时间线

按时间轴展示一次任务中各记忆的检索与写入时刻，分检索 / 写入 / 巩固 / 仲裁四条泳道，上方叠加记忆条目数曲线。

#### 标签页 4 · 冲突看板

待仲裁记忆对左右并排展示（含各自来源、时间、权威级别）+ 矛盾关系图 + 一键仲裁 + **影响提示**（「该裁决将影响 N 个历史研判的口径解释」）。

#### 标签页 5 · 用户记忆

各用户一张卡片：画像 + 偏好列表（标注来源是显式设置还是行为推断）+ 行为热力。支持两个用户并排对比，差异项高亮。

### 4.5 审计溯源（核心证据页）

| 区域 | 内容 |
|---|---|
| 顶部回放条 | 播放 / 暂停 / 速度档 / 进度条 / 快照选择 / 导出审计报告 |
| 左栏 Trace 树 | 按父子关系重建的因果树，节点显示智能体名、意图、耗时。**耗时超阈值的节点标红** |
| 中栏 节点详情 | 输入输出摘要 / 模型名与版本 / 提示词模板版本 / token / 耗时 / 引用的记忆 / 调用的技能 / 数据来源 / 规则包版本 / 置信度 |
| 右栏 统计 | 耗时占比桑基图 / 技能耗时排行 / 模型档位分布 / 降级与熔断事件清单 |

**回放机制的价值**：不仅是演示保险（模型变慢或网络抖动时按加速模式回放已保存的快照），在调试时同样有用——结论异常时，回放能精确定位到哪一步的消息内容不对。

**溯源链的五层表达**（贯穿全局的统一抽屉组件）：

```
结论字段
    ↓
消息（msg_id ｜ 智能体 ｜ 言语行为 ｜ 耗时）
    ↓
技能调用（各技能耗时 / 缓存命中 / 降级层级）
    ↓
记忆引用（各记忆标题 + 得分 + 是否被采用）
    ↓
数据来源（源系统 + 主键 + 关键字段值）
    ↓
模型与版本（模型名 ｜ 档位 ｜ 提示词版本 ｜ 规则包版本）
```

这五层下钻链路是整个「可信可审计」原则的最强证据。

### 4.6 简报中心

| 区域 | 内容 |
|---|---|
| 左栏 | 模板列表（值班版 / 监督版 / 灾情报告），随当前用户偏好自动切换 |
| 中栏 | 简报预览，分段展示，**每段末尾有引用角标**，悬停显示来源类型与具体依据 |
| 右栏 | 引用清单（可跳溯源）/ 版本历史 / 审批流状态 / 生成指标 |
| 操作条 | 重新生成全文 / 重生成选中段落 / 编辑 / 版本差异对比 / 提交审批 / 导出 |

**审批交互是记忆回填的触发点**：提交审批时弹出对话框（审批人、意见、采纳 / 修改后采纳 / 否决）。提交后提示「已生成程序记忆与反思记忆」，并提供跳转记忆中心的入口。

> 这个提示必须做——它是「人机协同闭环」从概念变成事实的那一瞬间。

### 4.7 技能与规则

| 标签页 | 内容 |
|---|---|
| 技能注册表 | 全部技能的健康度（调用次数 / 成功率 / P95 耗时 / 缓存命中率 / 降级次数），**每行带启用开关** |
| Agent Card | 各智能体卡片：能力标签、技能白名单、记忆权限、模型档位、失败策略 |
| 规则包 | 规则列表 + 可编辑的规则值 + 版本历史 + 保存并热更新 |
| 阈值试算 | 阈值滑块 + 实时影响预览（受影响区段数曲线、风险清单变化对比） |
| 模型路由 | 档位配置 + 路由规则 + 实时统计 |

**关闭某个技能开关后重跑任务**，可直观看到降级路径被触发——这是验证技能治理真实生效的最直接方式。

### 4.8 对话入口

| 区域 | 内容 |
|---|---|
| 对话区 | 每条回答下方有可折叠的「本次回答依据」，列出引用的记忆、调用的技能、数据来源 |
| 记忆影响面板 | 实时显示本轮注入的记忆（按得分排序）、调用的技能、模型档位、耗时。**可手动取消某条记忆的注入并重新生成** |
| 快捷指令 | 发起研判 / 查看待办 / 解释某区段风险 / 生成简报 |

> 「可手动取消记忆注入」这个交互很关键：它让「记忆影响输出」变成可被证伪的实验，而不是一句宣传语。

## 5. 可视化技术方案

| 需求 | 方案 | 理由 |
|---|---|---|
| 地图 | MapLibre + 离线行政区划数据 | 无 token 依赖，可完全离线，规避边界合规问题 |
| 时序图 | 自研（基于刻度计算） | 需支持实时增量追加，通用库适配成本高 |
| 拓扑图 | React Flow | 有向图布局与连线动效开箱可用 |
| 时序曲线 | ECharts | 多轴联动与缩放交互成熟 |
| 桑基图 / 瀑布图 | ECharts | 内置支持 |
| 消息流 | 自研 + 虚拟滚动 | 高频追加，需控制渲染开销 |

### 5.1 性能预算

| 场景 | 目标 |
|---|---|
| 首屏可交互 | < 1.5s（本地） |
| 事件洪峰下帧率 | ≥ 45 fps |
| 大规模区段地图渲染 | < 300ms |
| 长列表滚动 | 无白屏、无掉帧 |

## 6. 状态管理策略

三类状态严格分离，避免「所有东西都塞一个全局 store」的常见陷阱。

| 状态类型 | 载体 | 内容 | 更新频率 |
|---|---|---|---|
| 服务端状态 | 请求缓存库 | 任务结果、记忆列表、技能表、Trace 树、用户列表 | 按需 + 事件触发失效 |
| 实时事件缓冲 | 独立状态切片 | 事件队列、时序图数据点、消息流、拓扑活跃态 | 高频（节流批量提交） |
| 本地 UI 状态 | UI 状态切片 | 当前页、抽屉开合、筛选条件、开关与滑块 | 低频 |

### 6.1 三条工程约束

| 约束 | 做法 | 原因 |
|---|---|---|
| 事件节流批量提交 | 事件入队，每约 200ms 合并一次刷新 | 一次任务可能产生数百条事件，逐条更新会导致严重卡顿 |
| 长列表虚拟化 | 消息流、记忆表格、Trace 树全部虚拟滚动 | 记忆条数会随使用持续增长 |
| 时序图增量渲染 | 按事件追加元素 + 窗口裁剪，不整体重绘 | 全量重绘在大数据量下会掉帧 |

## 8. 实现要点与常见陷阱

| # | 陷阱 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 只做聊天界面 | 无法传递架构复杂度 | 机制可视化页面优先 |
| 2 | 事件逐条更新状态 | 高频事件下界面卡顿 | 节流批量提交 |
| 3 | 大列表不虚拟化 | 记忆增长后掉帧 | 虚拟滚动 |
| 4 | 使用在线地图底图 | 存在边界合规风险 | 离线行政区划数据 |
| 5 | 溯源只做到「跳转到日志」 | 无法形成完整证据链 | 五层下钻抽屉，全站统一 |
| 6 | 记忆内容不标注来源 | 无法验证记忆是否真被使用 | 命中高亮 + 访问历史 + 是否采用标记 |
| 7 | 缺少记忆开关与用户切换 | 记忆与个性化的效果无法验证 | 两个全局控件必须做 |
| 8 | 数字不启用等宽 | 指标跳动时界面抖动 | tabular-nums |
| 9 | 全站状态塞进单一 store | 高频更新引发全局重渲染 | 三类状态分离 |
| 10 | 演示依赖手动输入 | 现场易出错 | 预置场景一键触发 |
